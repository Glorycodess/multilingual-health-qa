## Competition Overview

**Competition:** [Zindi — Multilingual Health Question Answering](https://zindi.africa)

The goal is to build a model that generates accurate, fluent health-related answers in
low-resource African languages. Given a health question (`input`) the model must produce a
relevant answer (`output`) in the same language. The challenge spans eight language subsets
across four countries, several of which have minimal digital text resources, making this a
genuine low-resource NLP problem.

**Evaluation metrics:**

| Metric | Description |
|---|---|
| ROUGE-1 | Unigram overlap between generated and reference answer |
| ROUGE-L | Longest common subsequence overlap |
| LLM-as-a-Judge | A language model rates answer quality on a rubric (fluency, accuracy, completeness) |

**Approach:** Fine-tune `google/mt5-base` — a multilingual T5 variant pre-trained on the
mC4 corpus — using LoRA (Low-Rank Adaptation) via the PEFT library. LoRA freezes the base
model weights and trains a small set of rank-decomposition matrices, making it feasible to
fine-tune on free-tier GPU hardware (Colab T4 / Kaggle P100).

## Dataset

> **The data is not included in this repository.** Download it from the
> [Zindi competition page](https://zindi.africa) and place the files in the `data/` folder
> as described below.

### Splits

| Split | File | Rows | Columns |
|---|---|---|---|
| Train | `Train.csv` | 29,815 | ID, input, output, subset |
| Validation | `Val.csv` | 6,686 | ID, input, output, subset |
| Test | `Test.csv` | 2,618 | ID, input, subset |
| Sample submission | `SampleSubmission.csv` | 2,618 | ID, input, output, subset |

### Columns

| Column | Description |
|---|---|
| `ID` | Unique row identifier (e.g. `ID_TR_Aka_Gha_A3B1799D`) |
| `input` | Health question in the target language |
| `output` | Reference answer in the target language (absent in test set) |
| `subset` | Language / country code (see table below) |

### Language Subsets

| Subset code | Language | Country | Train examples |
|---|---|---|---|
| `Eng_Uga` | English | Uganda | 7,624 |
| `Aka_Gha` | Akan (Twi) | Ghana | 4,455 |
| `Eng_Gha` | English | Ghana | 4,443 |
| `Eng_Eth` | English | Ethiopia | 3,915 |
| `Lug_Uga` | Luganda | Uganda | 3,383 |
| `Eng_Ken` | English | Kenya | 2,080 |
| `Swa_Ken` | Swahili | Kenya | 2,070 |
| `Amh_Eth` | Amharic | Ethiopia | 1,845 |

**Note:** English variants (Uganda, Ghana, Ethiopia, Kenya) collectively make up ~60 % of
training examples. The three indigenous-language subsets (Akan, Luganda, Swahili, Amharic)
are underrepresented and likely harder for the model.

## Setup

### Prerequisites

- Python 3.9 or higher
- `pip` (or a conda environment)
- A GPU is **strongly recommended** for notebooks `03` onward. See
  [Training on Colab / Kaggle](#training-on-colab--kaggle) if you do not have local GPU access.

### 1 — Clone the repository

```bash
git clone https://github.com/<your-username>/multilingual-health-qa.git
cd multilingual-health-qa
```

### 2 — Create a virtual environment (recommended)

```bash
python -m venv .venv
source .venv/bin/activate       # Linux / macOS
# .venv\Scripts\activate        # Windows
```

### 3 — Install dependencies

```bash
pip install -r requirements.txt
```

### 4 — Download the data

1. Go to the [Zindi competition page](https://zindi.africa) and sign in.
2. Navigate to the **Data** tab and download all CSV files.
3. Place them in the `data/` folder:

```
data/
├── Train.csv
├── Val.csv
├── Test.csv
└── SampleSubmission.csv
```

The `data/` directory is gitignored so your local data will not be committed to the repository.

## Running the Notebooks

Run the notebooks **in order**. Each notebook reads the outputs of the previous one.

```bash
jupyter notebook notebooks/
```

| Step | Notebook | Description | GPU needed? |
|---|---|---|---|
| 1 | `01_data_exploration.ipynb` | EDA — language distribution, text length analysis, missing value checks, visualisations | No |
| 2 | `02_preprocessing.ipynb` | Whitespace normalisation, special-character validation, save `train_clean.csv`, `val_clean.csv`, `test_clean.csv` | No |

## Key EDA Findings

These findings (from `01_data_exploration.ipynb`) directly shaped preprocessing and
modelling decisions:

- **No missing values** across all three splits — the dataset is clean out of the box.
- **Language imbalance:** English variants make up ~60 % of training data; Amharic has the
  fewest examples (1,845). Models trained without weighting may underperform on indigenous
  languages.
- **Question length:** Mean 15 words, P95 ~35 words. A `max_input_length` of 128 tokens
  covers the vast majority of questions with minimal truncation.
- **Answer length:** Mean 76 words, P95 ~200 words, max 482 words. A `max_target_length`
  of 256 tokens covers ~90 % of answers; some long answers will be truncated.
- **Akan produces the longest answers** on average; Amharic the shortest.
- **Special characters** (ɔ, Ɔ, ɛ, ɲ, ŋ, ɣ) appear frequently in Akan and Luganda text.
  The mT5 SentencePiece tokenizer preserves these correctly — confirmed by a round-trip
  encode → decode test in `02_preprocessing.ipynb`.
- **Case must be preserved** — several African orthographies use capital letters to mark
  distinct phonemes (e.g. Ɔ vs ɔ in Akan). Lowercasing would silently corrupt the data.
